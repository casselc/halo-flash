# halo-flash

A narrow inference engine for one model, Qwen3.8-Flash-Next, on one
machine class: AMD Strix Halo (Ryzen AI MAX+ 395, gfx1151 iGPU, XDNA2 NPU,
128 GB unified memory). It runs on the HRX System runtime, with a ROCm HIP
backend kept for A/B comparison.

It will serve an OpenAI-compatible completions endpoint and expose a C ABI for
in-process embedding. The workload it is tuned for is a single user with a few
concurrent sessions, usually sharing a long common context.

Status: early bring-up. See [docs/PLAN.md](docs/PLAN.md) for the phased plan,
targets and quality gates.

## Building and testing

The core and the test suites need only clang, CMake and Ninja. GoogleTest and
[hegel-cpp](https://github.com/hegeldev/hegel-cpp) are fetched at configure
time.

```sh
cmake --preset cpu-asan && cmake --build --preset cpu-asan && ctest --preset cpu-asan
cmake --preset cpu-tsan && cmake --build --preset cpu-tsan && ctest --preset cpu-tsan
cmake --preset fuzz && cmake --build --preset fuzz && ./build/fuzz/gguf_fuzz -max_total_time=60
```

Tokenizer tests compare against fixtures generated by
`tools/gen_tokenizer_fixtures.py` from Python `unicodedata`, the `regex`
module and HF `tokenizers`. The encode comparison and the real-vocabulary
round trip run only when `HALO_FLASH_NEXT_GGUF` points at the first shard of
the Flash-Next GGUF; otherwise they report as skipped.

The tests are mostly properties and state machines written with Hegel. When a
property fails, Hegel shrinks it to a minimal counterexample and prints a
replay seed. Commit each one as a regression test.

## System One decisions (strands-decider)

`/v1/systemone` decisions run strands-decider-2B-hobson-v19 on the CPU
reference today. To build its artifacts from the Hugging Face checkpoints
(`LLAMA_CPP` points at a llama.cpp checkout with qwen35 support), run:

```sh
python $LLAMA_CPP/convert_hf_to_gguf.py models/Qwen3.5-2B-Base --outtype bf16 \
  --outfile models/Qwen3.5-2B-Base-BF16.gguf
LLAMA_CPP=... python tools/convert_lora_gguf.py models/Qwen3.5-2B-Base \
  models/strands-decider-2B-hobson-v19/lora models/strands-decider-lora-f32.gguf
LLAMA_CPP=... python tools/convert_decider_head.py models/strands-decider-2B-hobson-v19 \
  models/strands-decider-head.gguf
LLAMA_CPP=... python tools/tokenizer_json_to_gguf.py \
  models/strands-decider-2B-hobson-v19/tokenizer.json models/strands-decider-tokenizer.gguf
HALO_DECIDER_MODELS_DIR=$PWD/models ./build/release/decide_tests --gtest_filter='StrandsDecider.*'
```

The checkpoint's `hobson_config.json` names the base revision it was trained
on (`b1485b2`). Its `tokenizer.json` uses the older Qwen2 split regex, which
the tokenizer supports as the `qwen2` pre-tokenizer.
