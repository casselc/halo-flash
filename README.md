# halo-flash

A narrow inference engine for one model, Qwen3.8-Flash-Next, on one
machine class: AMD Strix Halo (Ryzen AI MAX+ 395, gfx1151 iGPU, XDNA2 NPU,
128 GB unified memory). It runs on the HRX System runtime, with a ROCm HIP
backend kept for A/B comparison.

It will serve an OpenAI-compatible completions endpoint and expose a C ABI for
in-process embedding. The workload it is tuned for is a single user with a few
concurrent sessions, usually sharing a long common context.

Status: correctness bring-up.
- The CPU references match HF transformers for Flash-Next and Qwen3.5,
  including LoRA.
- On the GPU (HIP and HRX), Flash-Next decodes the tiny test model with
  graph replay and session snapshots.
- The strands-decider runs end to end.
- Speed work (P3) and the real-weight quality gates are next.

See [docs/PLAN.md](docs/PLAN.md) for the phased plan, targets and quality
gates, [docs/P0-BASELINES.md](docs/P0-BASELINES.md) for measurements, and
[docs/N-LANE.md](docs/N-LANE.md) for NPU results.

## Building and testing

The core and the test suites need only clang, CMake and Ninja. GoogleTest and
[hegel-cpp](https://github.com/hegeldev/hegel-cpp) are fetched at configure
time.

```sh
cmake --preset cpu-asan && cmake --build --preset cpu-asan && ctest --preset cpu-asan
cmake --preset cpu-tsan && cmake --build --preset cpu-tsan && ctest --preset cpu-tsan
cmake --preset fuzz && cmake --build --preset fuzz && ./build/fuzz/gguf_fuzz -max_total_time=60
```

Tokenizer tests compare against fixtures generated by
`tools/gen_tokenizer_fixtures.py` from Python `unicodedata`, the `regex`
module and HF `tokenizers`. The encode comparison and the real-vocabulary
round trip run only when `HALO_FLASH_NEXT_GGUF` points at the first shard of
the Flash-Next GGUF; otherwise they report as skipped.

The tests are mostly properties and state machines written with Hegel. When a
property fails, Hegel shrinks it to a minimal counterexample and prints a
replay seed. Commit each one as a regression test.

## Planted mutants

Every entry in `tests/mutants.toml` is a deliberate defect that some test must
catch:

```sh
HALO_TINY_HF_DIR=... HALO_TINY_QWEN35_DIR=... tools/mutants.py         # all
tools/mutants.py -k snapshot                                           # by name
python3 -m unittest tools/mutants_test.py                              # anchors still match
```

The runner refuses to judge unless each suite passes unmutated with nothing
skipped. A mutant that doesn't compile is reported INVALID, never killed. When
a mutant survives, add the missing test; if it is equivalent, replace it and
say why in its `why`.

## Mutation testing with Mull

[Mull](https://github.com/mull-project/mull) 0.34 (the build for LLVM 21)
mutates the host libraries named in `mull.yml` and checks that some test fails
for each mutant. Unpack its `.deb` anywhere (`dpkg-deb -x Mull-21-*.deb
$MULL_ROOT`) and point `MULL_ROOT` at it:

```sh
export MULL_ROOT=...            # contains usr/bin/mull-runner-21
cmake --preset mull && cmake --build --preset mull
export CI=1                     # Hegel derandomizes under CI: same inputs for every mutant
for t in core text decide model; do
  $MULL_ROOT/usr/bin/mull-runner-21 --reporters SQLite --reporters IDE --report-dir build/mull/report \
    --report-name $t --allow-surviving --no-output --minimum-timeout 60000 build/mull/${t}_tests
done
python3 tools/mull_survivors.py summary build/mull/report/*.sqlite
python3 tools/mull_survivors.py keys build/mull/report/*.sqlite > build/mull/survivors.txt
python3 tools/mull_survivors.py check tests/mull-baseline.txt build/mull/survivors.txt
```

Delete the `.sqlite` reports before a rerun: Mull appends to them. A mutant's
timeout is ten times the unmutated run or `--minimum-timeout`, whichever is
larger (`--timeout` bounds only the unmutated run); a timeout counts as
killed, so keep the minimum generous when the machine is busy. Set the
fixture variables first (`HALO_TINY_HF_DIR`, `HALO_TINY_QWEN35_DIR`,
`HALO_DECIDER_TOKENIZER_GGUF`), or the tests that need them skip and their
mutants survive. The end-to-end decider test (`HALO_DECIDER_MODELS_DIR`) is
too slow to run per mutant; leave it unset.

`check` fails on a survivor that is not in `tests/mull-baseline.txt`. A
survivor's key is its file, enclosing function and mutator, so it does not move
when lines do. For a new survivor, write the test that kills it, or, if no test
can observe it, add its key to the baseline with a one-line reason
(`key | reason`). `check` also lists baseline entries that no longer survive;
delete them. `python3 tools/mull_survivors_test.py` tests the script.

## System One decisions (strands-decider)

`/v1/systemone` decisions run strands-decider-2B-hobson-v19 on the CPU
reference or the GPU (`HALO_DECIDER_DEVICE=hip|hrx`). To build its artifacts from the Hugging Face checkpoints
(`LLAMA_CPP` points at a llama.cpp checkout with qwen35 support), run:

```sh
python $LLAMA_CPP/convert_hf_to_gguf.py models/Qwen3.5-2B-Base --outtype bf16 \
  --outfile models/Qwen3.5-2B-Base-BF16.gguf
LLAMA_CPP=... python tools/convert_lora_gguf.py models/Qwen3.5-2B-Base \
  models/strands-decider-2B-hobson-v19/lora models/strands-decider-lora-f32.gguf
LLAMA_CPP=... python tools/convert_decider_head.py models/strands-decider-2B-hobson-v19 \
  models/strands-decider-head.gguf
LLAMA_CPP=... python tools/tokenizer_json_to_gguf.py \
  models/strands-decider-2B-hobson-v19/tokenizer.json models/strands-decider-tokenizer.gguf
HALO_DECIDER_MODELS_DIR=$PWD/models ./build/release/decide_tests --gtest_filter='StrandsDecider.*'
```

The checkpoint's `hobson_config.json` names the base revision it was trained
on (`b1485b2`). Its `tokenizer.json` uses the older Qwen2 split regex, which
the tokenizer supports as the `qwen2` pre-tokenizer.
